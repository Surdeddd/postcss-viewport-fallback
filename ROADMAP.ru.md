# Roadmap

English: [ROADMAP.md](./ROADMAP.md)

## Что плагин умеет сегодня

- Fallback-и для **всех 18** viewport-единиц CSS Values 4 (`sv*`, `lv*`, `dv*` × `w/h/i/b/min/max`), на любой глубине `calc()`, `min()`, `max()`, `clamp()`, с пробелами вокруг операторов и без них
- Две стратегии: `duplicate` (статический двойник, в бандл ничего не попадает) и `css-var` (`calc(var(...))`, seed и необязательный runtime на 1.1 КБ в синтаксисе ES5, который даёт старым браузерам живые значения `dv*`)
- Значения с `var()` / `env()` и пользовательские свойства получают fallback, который действительно применяется: fallback остаётся в правиле, оригинал уходит под `@supports` вместе с более поздними объявлениями, которые могут с ним пересечься
- Таблица шортхендов, лонгхендов, псевдонимов и логических свойств, собранная по спецификациям CSS и сверенная с Chrome, говорит, какие объявления пересекаются: повторяются только они, а свойство, которого в таблице нет, считается связанным с любым другим
- Одна проба `@supports (height: 1dvh)` на все встроенные единицы; соседние объявления делят один блок
- `@media`, `@import` и `@custom-media` получают пониженный запрос ещё одним элементом списка; `@container` — правило-двойника; `@keyframes` со значениями с `var()` и `@property` с `initial-value` повторяются под `@supports`, по разу на каждый шаг цепочки единиц
- Feature query `@supports` никогда не переписываются, а то, что под их защитой, не получает fallback; условия с `not`, `and`, `or` вычисляются по единицам, которые они гарантируют
- Fallback, написанный вами, распознаётся там, где он занимает то же место в каскаде, в том числе через объявления несвязанных свойств (`existingFallback: 'exact' | 'any'`)
- Логические единицы по умолчанию понижаются до физических (`logicalFallback`)
- Фрагменты CSS-in-JS могут получать вложенные блоки `@supports` (`fragmentGuards`); seed стратегии css-var можно подключить один раз (`seed: false` + `postcss-viewport-fallback/seed.css`)
- Собственные соответствия единиц (`customUnits`) с цепочками и поиском циклов
- Автопропуск по `browserslist`, который определяется для каждого обрабатываемого файла; `fastSkip`
- Фильтры свойств, точечные управляющие комментарии и диапазоны, режим `strict` для CI, пресеты debug, `onTransform` / `onComplete`
- Опции проверяются при создании плагина, включая неизвестные имена; сообщения на английском или русском (`PVF_LANG=ru`)
- Работает после плагинов, обходящих узлы (`postcss-nesting`, `postcss-logical`, `postcss-preset-env`), поэтому их порядок в конфиге не меняет результат
- Загрузка через `postcss-load-config`, `import` и `require`; точные source maps; безопасная работа над многими файлами одновременно
- [Песочница](https://surdeddd.github.io/postcss-viewport-fallback/) запускает плагин прямо в браузере: вставить CSS, переключить опции, увидеть, какие строки написал плагин, скопировать конфиг или ссылку на результат

## Идеи на рассмотрении

### Отказ от двойника `@container`

Когда списки условий в container queries станут поддерживаться повсеместно, `@container` можно будет обрабатывать как `@media`: ещё одно условие в списке вместо второго правила.

### Пользовательские единицы в runtime

Runtime покрывает встроенные единицы. Он мог бы принимать карту `customUnits` и поддерживать живыми и эти переменные.

### `@keyframes` и `@property` по комбинациям проб

Такое правило повторяется целиком, поэтому значения, которым нужны разные пробы, например двум несвязанным `customUnits`, повышаются вместе: браузер, который знает только одну из единиц, остаётся на fallback для обеих. Копия на каждую комбинацию проб повышала бы каждое значение отдельно, ценой до 2ⁿ − 1 копий. Имеет смысл, когда кто-то действительно сопоставит несколько независимых единиц.

### Seed, который доходит до каждого атрибута style

Со стратегией `css-var` seed для атрибутов `style=""` уходит в первый блок `<style>` документа. Если этот блок к элементу не применяется (атрибут `media`, shadow root), атрибут остаётся на fallback даже в браузерах, которые знают единицу. Выбор блока, который действует, или предупреждение, когда такого нет, закрыли бы этот пробел.

### Узнаваемость

Попасть в список на [postcss.org](https://postcss.org/docs/postcss-plugins) и сделать отдельные страницы с рецептами для распространённых фреймворков.

### Пакет только в формате ESM

Стоит рассмотреть, когда закончится поддержка Node 20.

## Сознательно вне рамок

- **Переписывание feature query `@supports`.** Версии 1.x превращали `@supports (height: 100dvh)` в дополнительный блок `@supports (height: 100vh)`. Это открывает всем стили, которые автор закрыл намеренно, и ломает написанные вручную лесенки, поэтому в 2.0 это убрано насовсем.
- **Ограждение пониженного media-запроса.** Обёртка в `@supports not (height: 1dvh)` не дала бы современным браузерам его вычислять, но ценой повторного дублирования блока — того самого, чего список запросов позволяет избежать. Узкий случай, который она исправила бы, описан в README в разделе «Известные ограничения».
- **Режим подсказок или lint.** Предупреждать о `dvh` на фиксированных или анимируемых элементах — задача правила stylelint, а не трансформации.
- **Объекты inline-стилей в JSX, Angular или Svelte.** Для них нужен плагин компилятора, а не PostCSS. `postcss-html` уже покрывает блоки `<style>` и атрибуты `style=""`.
- **Режим `-webkit-fill-available`.** Отживший приём (только WebKit, ломается в `calc()`, только высота) для аудитории намного меньше 1%. Эту нишу занимает `postcss-100vh-fix`.
- **Интеграция с LightningCSS.** LightningCSS намеренно не понижает viewport-единицы ([issue #534](https://github.com/parcel-bundler/lightningcss/issues/534)); этот плагин спокойно работает рядом с ним.
