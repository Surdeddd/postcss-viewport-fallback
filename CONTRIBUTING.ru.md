# Участие в разработке

English: [CONTRIBUTING.md](./CONTRIBUTING.md)

Спасибо, что нашли время. Сообщение об ошибке с небольшим примером CSS ценно не меньше кода.

## Сообщение об ошибке

С сообщением легко работать, когда в нём есть:

- CSS на входе и CSS на выходе (достаточно нескольких строк)
- опции плагина и остальные PostCSS-плагины в пайплайне, по порядку
- версии `postcss-viewport-fallback`, `postcss` и Node
- что вы ожидали увидеть и в каком браузере результат неверный

## Подготовка

```bash
git clone https://github.com/Surdeddd/postcss-viewport-fallback.git
cd postcss-viewport-fallback
npm ci
npm test
```

Нужен Node 20 или новее.

## Как внести изменение

1. Напишите тест, который падает по той причине, которую вы собираетесь устранить. Тесты лежат в `test/`, по одной теме на файл; `test/helpers/run.ts` прогоняет плагин по строке.
2. Добейтесь прохождения минимальным изменением.
3. Прогоните все проверки:

```bash
npm run lint
npm run typecheck
npm run test:coverage   # coverage thresholds are 100%
npm run build
npm run check:package   # publint, arethetypeswrong, smoke test, type fixtures
```

Особенности проекта:

- **Оракул каскада** (`test/cascade-oracle.test.ts`) генерирует случайный CSS и для нескольких моделей браузера проверяет, что каждая пара `селектор | свойство` получает значение, задуманное автором. Если он падает, в сообщении есть вход и выход; прежде чем чинить, сведите их к маленькому тесту.
- **Таблица свойств** (`src/core/properties.data.ts`) генерируется, руками её не правят. `npm run properties` собирает её из `@webref/css` и из `scripts/data/chrome-shorthands.json` — записи того, что Chrome устанавливает через каждый известный ему шортхенд и псевдоним (эту запись выдаёт `scripts/data/capture-shorthands.js` в консоли браузера). Чтобы обновить таблицу, обновите `@webref/css`, запустите скрипт и закоммитьте результат; пока таблица в репозитории устарела, падает тест. Оракул намеренно держит собственную, написанную руками модель шортхендов: две модели должны сходиться.
- **Песочница** лежит в `playground/`. `npm run playground` собирает её в `playground/dist`: плагин в сборке для браузера и собственная таблица стилей страницы, пропущенная через плагин. Она публикуется на GitHub Pages при изменении `main`; её логика, которой не нужен DOM, покрыта в `test/playground.test.ts`.
- **Другие плагины проверяются настоящие.** PostCSS вызывает плагин, подписанный на отдельные свойства, после плагинов, подписанных на все объявления, поэтому плагины, делящие один обход, меняют узлы друг друга при любом порядке в конфиге. Вот почему этот плагин работает после обхода, когда узлы обходит кто-то ещё (`src/plugin/index.ts`). `test/real-plugins.test.ts` запускает его до и после `postcss-logical` и `postcss-nesting`, а `test/other-plugins.test.ts` фиксирует, что обещано про другие плагины; оба порядка обязаны давать один и тот же CSS.
- **Поведение браузеров проверяется в браузере.** Если изменение опирается на то, как CSS разбирается или каскадируется, сначала проверьте это в реальном движке. Несуществующая единица (`1qq`) удобно заменяет «браузер без `dvh`».
- **Runtime** (`src/runtime.ts`) попадает в старые браузеры без транспиляции: только синтаксис ES5. За этим следит ESLint.
- **Сообщения** берутся из каталога в `src/core/messages.ts`, на английском и русском.
- **Документация** ведётся парами: `README.md` + `README.ru.md`, `ROADMAP.md` + `ROADMAP.ru.md`.
- `CHANGELOG.md` пишет semantic-release. Не правьте его вручную.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org), на английском: `fix: …`, `feat: …`, `docs: …`, `test: …`, `chore: …`. Ломающее изменение сопровождается футером `BREAKING CHANGE:`. Релизы выпускаются автоматически по этим сообщениям при обновлении `main`.
